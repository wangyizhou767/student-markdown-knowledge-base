# 测试与验收计划

## 1. 记录原则

- “通过”只能填写在实际执行并得到预期结果之后；
- 每次测试记录测试日期、提交号、Windows 版本和执行人；
- 自动测试输出、界面截图和真实磁盘文件均可作为证据；
- 未实现功能标记为“待实现”，不能用“未发现问题”代替测试；
- 数据丢失、无法启动、新建或保存失败均为发布阻塞问题。

## 2. 自动检查

仓库的 `.github/workflows/desktop-check.yml` 会在 `main` 更新和 Pull Request 时运行：

1. Node 主进程与 preload TypeScript 检查；
2. React 界面 TypeScript 检查；
3. Vitest 自动测试；
4. electron-vite 构建。

组员提交 Pull Request 后，必须等待“桌面端自动检查”通过。自动检查不能代替真实文件操作和打包程序的人工验证。

本地执行命令：

```powershell
cd apps/desktop
pnpm exec tsc -p tsconfig.node.json --noEmit
pnpm exec tsc -p tsconfig.web.json --noEmit
pnpm test
pnpm build
```

## 5. 人工验收知识库

仓库提供 `docs/acceptance-vault/`。测试时先把整个目录复制到仓库外的临时位置，再用软件打开副本，避免把测试产生的修改提交到 GitHub。

示例包含中文标题、英文标题、嵌套目录、不同目录同名笔记、代码块、列表、Wiki 链接文本和无 YAML 元数据的旧笔记。
