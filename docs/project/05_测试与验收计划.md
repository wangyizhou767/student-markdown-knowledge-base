# 测试与验收计划

## 发布门槛

下列核心场景全部通过后才生成最终 Release：

| 编号 | 场景 | 通过条件 |
|---|---|---|
| MVP-E2E-01 | 首次创建知识库和笔记 | 目录及 `.md` 文件真实存在，重启后仍可打开 |
| MVP-E2E-02 | 编辑、手动保存和自动保存 | 状态提示与磁盘内容一致，失败时编辑缓冲区不丢失 |
| MVP-E2E-03 | Markdown 安全预览 | 常用语法正确；脚本、事件属性和危险协议不执行 |
| MVP-E2E-04 | 搜索 | 标题和正文可命中；保存、重命名、删除后结果更新 |
| MVP-E2E-05 | Wiki 链接与反向链接 | 可打开唯一目标；缺失和同名目标不误跳转 |
| MVP-E2E-06 | 删除与恢复 | 删除后进入 `.pkm/trash/`；恢复后内容哈希一致 |
| MVP-E2E-07 | 路径和名称安全 | `..`、绝对路径、Windows 非法名称和越界目标被拒绝 |
| MVP-E2E-08 | 外部变化 | 磁盘版本变化时不以旧缓冲区静默覆盖，并提示重新加载 |
| MVP-E2E-09 | Windows 构建 | 打包产物可在无开发服务器的环境中启动并完成核心流程 |
| MVP-E2E-10 | 异常退出后数据检查 | 已成功保存内容保留；临时文件不被误当正式笔记 |

## 测试分层

- 单元测试：路径、名称、Markdown 链接解析、搜索索引和状态转换；
- 集成测试：preload 到主进程的知识库、笔记、保存和回收站接口；
- 端到端测试：按 MVP-E2E-01～10 执行真实文件操作；
- 人工测试：界面、错误提示、安装包和不同 Windows 缩放；
- 用户试用：至少 3 名目标用户完成统一任务并记录时间、失败点和意见。

## 真实用户任务

1. 打开指定知识库并新建课程笔记；
2. 输入标题、列表、代码块和一个 Wiki 链接；
3. 保存并通过搜索重新找到该笔记；
4. 打开链接目标并查看反向链接；
5. 删除笔记，再从回收站恢复。

反馈记录只写实际观察结果，不补填未发生的数据。严重数据丢失、无法启动或核心流程阻断均为发布阻塞缺陷。
