这是启动阶段的默认分配；实际开发时可根据进度互相支援，但每项任务仍保留一名明确主负责人。

在尚未根据个人技能调整前，采用以下默认分工：

| 角色 | 主要所有权 | 不得单独决定的事项 |
|---|---|---|
| 成员 A 桌面与文件层 | Electron 主进程、preload、知识库、文件读写、重命名、回收站 | IPC 契约和共享类型变更需三人同步 |
| 成员 B 界面与编辑 | React 工作区、文件树、编辑器、Markdown 预览、状态与错误提示 | 不直接在界面层访问 Node 或文件系统 |
| 成员 C 检索与质量 | 搜索索引、Wiki 链接/反向链接、自动测试、打包、手册和反馈整理 | 不在最后两天单独加入新功能 |

三人共同负责每日集成、Pull Request 审查、演示脚本和最终报告。每个功能只有一名主负责人，但至少一名其他成员负责审查和复测。
