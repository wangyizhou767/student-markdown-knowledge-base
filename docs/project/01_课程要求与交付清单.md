# 课程要求与交付清单

## 课程硬性要求

根据课程项目任务书，本项目按三人团队实施，并满足以下要求：

- 使用现代软件工具和软件工程方法完成可用软件；
- 每项团队任务均有可见结果；
- 代码签入不少于 10 次，且不同版本具有实际修改量；
- 保留阶段性文档；
- 提供真实用户使用和反馈记录；
- 在仓库中管理任务和缺陷；
- 第二次验收展示功能运行与测试结果；
- 坚持原创，保留成员分工和开发过程证据。

GitHub 与任务书建议的平台具有等价的 Git 托管、协作者、提交历史和 Issues 能力，本团队统一使用 GitHub。

## 最终交付物

| 交付物 | 仓库位置或形成方式 | 完成标准 |
|---|---|---|
| 源代码和工程文件 | `apps/desktop/` | 新环境按 README 可安装、启动和构建 |
| 可独立运行程序 | GitHub Release 和提交压缩包 | Windows 10/11 可启动，不要求开发环境 |
| 简要操作手册 | `docs/project/操作手册.md` | 覆盖安装、知识库、编辑、搜索、链接、回收站和退出 |
| 软件工程项目报告 | `docs/project/项目报告.md` | 说明需求、设计、实现、测试、分工、过程和结果 |
| 需求与设计基线 | `docs/baseline/` | 保留作业一、作业二成果及实现范围映射 |
| 测试计划和结果 | `docs/project/05_测试与验收计划.md` 及测试输出 | 核心流程全部通过，失败项有记录 |
| 用户反馈 | `docs/user-feedback/` | 至少 3 名目标用户的任务、结果、意见和改进记录 |
| 过程证据 | GitHub commits、Issues、PR | 至少 10 次有效提交，三名成员均有可见贡献 |
| 演示材料 | `docs/project/demo/` | 演示脚本、截图，时间允许时录制视频 |

## 评分优先级

课程评价中，需求分析占 20%，设计占 35%，编码与测试占 30%，创意占 10%，真实用户反馈占 5%。现有需求和设计已经较完整，本周应把主要时间投入稳定实现、测试、提交历史和用户反馈，避免继续扩写低优先级设计。
